⚙️ 首次設定 Firebase 專案（展開）

從 Firebase 控制台的「專案設定 → 你的應用程式 → 網頁應用程式 → Config」複製 firebaseConfig 物件，貼到下面。設定值會寫進你下載的公開 HTML，但不會包含私人旅遊資料。

儲存後請到下方按「下載可部署的 index.html」，並將它上傳 GitHub Pages，其他裝置就能使用同一個 Firebase 設定。更換專案設定後需重新下載部署。

🧭 Firebase 控制台操作提示（展開）
  1. 到 Firebase Console ↗ 建立專案並加入 Web App。
  2. Authentication → Sign-in method 啟用 Google 登入。
  3. Authentication → Settings → Authorized domains 新增 你的帳號.github.io（不要加 https:// 或 /kyoto-trip）。
  4. Firestore Database 建立 Standard 資料庫，並在 Rules 貼上下面規則後 Publish（不要使用 Test mode 公開規則）。
  5. 貼上 Web App 設定 → 按「儲存設定並重新載入」→ Google 登入 → 測試一筆待辦 → 下載並部署 index.html。
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /trips/{userId} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
  }
}

🔒 所有使用者只能存取自己 Google 帳號 UID 的行程文件；不會互相看見。資料存放於 trips/{uid}。本版以每人一份行程文件同步，若多台裝置同時編輯有衝突，會提醒選擇版本。請避免上傳私人 JSON 或含私人資料的舊 HTML 到公開 GitHub。

10 / KEEP IT SAFE

資料與備份

網站程式與私人行程分開保存，避免把訂房資料不小心發布到 GitHub。

兩種下載的差別：「可部署 HTML」只包含網站／Firebase 設定，不包含個人行程，可以安全上傳 GitHub Pages；「JSON 私人備份」會包含你填的行程與訂房資訊，請妥善保管。Google Fonts 與 Firebase SDK 需要網路載入。
